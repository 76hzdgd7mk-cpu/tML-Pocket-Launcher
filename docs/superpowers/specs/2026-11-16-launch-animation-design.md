# 游戏启动动画：玻璃启程

## 范围与交付

设计稿经确认后已接入 0.1.8 正式 Android 启动流程。独立预览保留成功、校验失败、持续等待、横竖屏、减弱动态和慢速回放；预览的示例时长仅用于观看设计，正式版本由真实校验、运行环境与首帧事件驱动。

## 视觉方向

延续当前启动器的深色液态玻璃、克制标题和紧凑控件。以现有 tModLoader 像素树与齿轮标识作为视觉中心，周围两条细光弧使用低饱和叶绿色与灰白色，玻璃光泽使用静态透明渐变和细边缘。背景是深色中性底，无森林插画。仅四个低亮像素光点呼应 Terraria，保留充分留白。

比较了三个方向：仅在按钮内显示进度最轻，但进入 GameActivity 时容易出现突兀切换；整屏像素场景辨识度高，但与用户此前取消背景风格的要求不符；推荐从按钮展开的轻玻璃启动层，衔接当前 UI 并为游戏画面交接留出空间。

## 动效时序

1. 按下：沿用 RippleButton，约 120ms 的 0.97 倍按压反馈；立即锁定重复启动。
2. 展开：450ms，从启动按钮矩形向容器全屏展开轻玻璃层；使用 clip-path，位移动效采用现有曲线。标识在约 170ms 后以 250ms 淡入和 8px 上移出现。
3. 校验与等待：标识保持稳定，外光弧每 4.5 秒匀速转动，内光弧反向缓慢转动；四个短步骤标记表示已经收到的真实阶段事件，不显示虚构百分比。状态文字以 160ms 淡入和 4px 位移切换。日志入口始终位于底部，正文保持单一主状态。
4. 交接：收到游戏已准备显示的事件后，启动层 250ms 淡出，标识最多放大至 1.025 倍。无固定倒计时、强制完整播放或人为延迟游戏显示。

所有渐变、阴影与背景不逐帧变化。常态动画只改变 transform/opacity，展开层使用 clip-path。暂停、速度与模拟结果仅属于设计稿外部工具栏。

## 与真实启动流程衔接

当前 LaunchDock 调用 nativeRequest('launch')；MainActivity 执行 launch.check，成功后进入 GameActivity。launch.check 会检查安装、Steam 来源的所有权、模组依赖和补丁参数。GOG 来源不新增 Steam 校验。

正式接入时应把启动动效封装成独立的 launch-transition 功能，状态为 idle / checking / handingOff / waitingForFrame / failed，不借用普通下载任务弹窗。资源检查、Steam 验证（仅 Steam）、模组与补丁检查、运行环境准备均由原生实际事件驱动。首次启动、慢设备与复杂模组保持等待状态，不重复制造已经完成的步骤。

WebView 覆盖层只能覆盖当前启动器 Activity。进入 GameActivity 后，需以同样的底色和标识做原生启动覆盖层，直到游戏首次呈现画面再淡出；单纯收到 launch.check 成功或 startActivity 返回不能显示“游戏已加载完成”。如果原生首帧信号暂时不可用，应标注“正在进入游戏”并保留诚实的等待语义。

## 错误与返回

校验失败立即停止循环，保留标识和单行错误原因，呈现“重新尝试 / 返回启动器”，日志为次要入口；Steam 权限错误可将主操作替换为“前往 Steam”。返回、失败和 Activity 恢复需清理启动状态，恢复原按钮焦点与交互。不能以动效完成代替真正启动成功。

持续等待不自动报失败，不填满进度。日志显示真实启动输出。游戏进程退出或 Activity 返回时应回到可操作的启动器，保留错误信息供查看。

## 适配与无障碍

横屏中心标识约 110–162px，顶部版本为辅助信息；竖屏标识约 145px，状态与底部日志保持明确间距。正式接入沿用当前主题变量、启动方向和安全区，不增加大标题或常驻侧栏。

预览的标识、进度状态、错误操作与日志页脚采用同一个 Grid 顺序排布，不分别用百分比定位。短窗口使用容器查询缩小标识并收紧次要间距；设计画布最小高度为 340px，确保预览侧栏变窄时也不会重叠或裁掉内容。标识按容器高度调整，小窗口可缩至 64px。

遵循应用动效开关及 prefers-reduced-motion：取消旋转、漂浮、位移与扩张，仅保留约 120–160ms 不透明度交接。状态使用 aria-live=polite，装饰图形对辅助技术隐藏。真实接入使用现有受控弹层的焦点管理；预览外部工具栏不属于产品 UI。

## 验证标准

预览在桌面、手机横屏和竖屏无水平溢出；成功、失败、持续等待、重播、日志和减弱动态可独立观看；暂停后不继续跳步骤。正式集成测试覆盖重复启动、校验失败、日志、重试、Steam 引导、返回恢复、减弱动态及五种横竖屏尺寸的元素间距。首帧信号测试要求呈现失败时不能隐藏覆盖层，成功后只通知一次。

0.1.8 实机已验证进入游戏进程、错误日志和返回恢复，但当时导入的 tML 2026.09.3.1 被已有兼容层错误阻断：`DetectAbnormalSteamWorkshopDownloads` 含 out 参数，运行时补丁不支持该签名。

后续 0.1.9 已修复 out 参数适配及桌面 SteamGameServer 初始化问题。相同实机资源现已通过模组初始化、真实游戏首帧淡出，进入中文主菜单及角色选择界面。未创建角色或世界，实际世界内游玩不属于本次启动验证。
